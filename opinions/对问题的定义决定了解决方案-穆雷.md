# 对问题的定义决定了解决方案

**主张**：问题是创意的基础，对问题的定义决定了解决问题的方式——把它定义为岛就需要建造木筏，把它定义为半岛走着去就行；好的登山鞋胜过复杂的造船工程，前提是你正确定义了问题。

**反常识在哪**：大众印象中"创意=解决方案的灵光一现"，穆雷反转——创意的80%在前端的问题定义，而不是后端的方案生成。这与韦德尔-韦德尔斯堡"重新定义问题比解决问题更重要"的论断直接呼应：定义错了，再精巧的方案都是浪费。

**核心证据/论据**：
- **湖心岛寓言**：穆雷小时候想造木筏去湖心岛，花一整天造船差点淹死，到达后发现岛其实是半岛——沿湖岸走过去就行。"我已经为我的问题设计了一个复杂的解决方案，一个复杂的木筏，我还花了整整一天时间来造船，其实我需要做的就是沿着湖岸走"
- **核心命题**："问题是创意的基础。"——创意建立在"试图解决哪个问题"上
- **定义的三个层次**：
  1. 识别问题（到底要解决什么）
  2. 确定根源（问题背后的真正原因）
  3. 理解范围（问题的边界在哪）
- **达尔文的反思**："回想起来，我认为我的成功在于我能够长时间地思考一个问题"——定义问题的耐力
- **与建筑比喻的呼应**：问题=地基，地基打歪了，房子再漂亮也是危房

**可被挑战**：
- "定义决定方案"过于决定论——同一问题定义可以有多种解决方案，方案质量也取决于执行
- 湖心岛寓言是事后回溯，可能存在"幸存者偏差"——失败的定义案例不会被记住
- 在紧迫的商业环境中，过度定义问题可能错失市场窗口——敏捷开发强调"边做边定义"
- 与 [[重新定义问题优于解决问题-韦德尔-韦德尔斯堡|韦德尔斯堡论重新定义问题]] 互补但需注意：韦德尔斯堡强调"重新定义"（45度重述），穆雷强调"首次定义"——两者结合更完整
- 在某些场景（如科学发现），问题定义本身就需要大量探索才能清晰，不能预设"先定义后解决"的线性顺序
- 定义问题的能力本身依赖经验和领域知识——新手可能根本不知道有哪些定义方式
