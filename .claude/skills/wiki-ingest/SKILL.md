# Wiki Ingest — 长书分章节阅读 & Ingest

## 触发条件

用户说：
- `/wiki-ingest <pdf路径>`
- `/wiki-ingest`（无路径）
- "帮我逐章读这本书"
- "分章节阅读 <pdf>"
- `/wiki ingest <pdf>` 且 PDF 超过 30 页

---

## 核心流程

### 第 0 步：初始化

1. **确定 PDF 路径**：
   - 若用户提供了路径或消息中包含文件附件，直接使用
   - 若无路径：运行 `ls -t /Users/zhuqichen/MySpace/my-wiki/.cc-connect/attachments/*.pdf | head -1` 取最新 PDF，**直接使用，不询问用户**
2. 读取 wiki CLAUDE.md（`/Users/zhuqichen/MySpace/my-wiki/CLAUDE.md`）
3. 读 `hot.md` 获取近期上下文
4. 读 PDF 前 5 页，获取：书名、作者、出版信息
5. 读目录页（通常在第 2-10 页），提取章节列表和页码

输出章节列表，格式：
```
📚 《书名》 — 作者
共 N 章 / M 页

章节列表：
  第1章 章节名（第X-Y页）
  第2章 章节名（第Y-Z页）
  ...

准备开始逐章阅读。输入"继续"开始第1章，或指定"第N章"跳转。
```

---

### 第 1 步：逐章阅读

对每章执行以下循环：

#### 1a. 读取章节内容

- 每次调用 Read 工具最多读 20 页（硬限制）
- 若章节超过 20 页，分多次读取，拼接理解
- 读取时静默处理，不输出原文

#### 1b. 提炼章节洞见

阅读完本章后，输出：

```
---
## 第N章：《章节名》（第X-Y页）

**核心论点**
一句话总结本章最重要的主张。

**关键洞见**（2-4条）
• 洞见1：...
• 洞见2：...
• 洞见3：...

**金句 / 原话**（可选）
> "引用原文..."

**与前章的关联**（第2章起）
→ 本章如何发展/对比/印证前章的论点

---
[回复"继续"读下一章 | "跳到第N章" | "先停这里" | "开始写页面"]
```

#### 1c. 更新运行中的知识地图

在内存中维护一个 `knowledge_map`，结构：
```
{
  "主题A": {
    "concepts": ["框架/定义洞见（第2章）"],
    "opinions": ["强主张（作者观点，第5章）"]
  },
  ...
}
```
每读完一章，将新洞见归类到主题下，并区分是「概念/框架」还是「强命题/观点」。不输出给用户，仅内部使用。

---

### 第 2 步：阶段性总结（可选）

用户说"总结一下"或读完全书后，输出跨章综合：

```
## 全书知识地图

**贯穿全书的核心主题**
1. 主题A — 出现于第X/Y/Z章
2. 主题B — ...

**作者的核心论证链**
第1章 → 第2章 → ... （一句话描述逻辑链）

**最具原创性的3个洞见**
1. ...
2. ...
3. ...

**与已有知识的关联**（参考 wiki）
• 与[[已有页面A]]的关系：...
```

---

### 第 3 步：写入 Wiki

用户确认后（说"开始写"或"ingest"），执行：

#### 3a. 规划页面结构

根据知识地图，提议创建的页面：

```
建议创建以下页面：

concepts/（中性知识单元：框架/定义/工具）
  • 主题A.md — 核心概念页
  • 主题B.md — ...

opinions/（强命题：作者的主张，可被质疑）
  • 命题标题-作者名.md — 一条强主张一页
  • ...

sources/
  • 书名-来源摘要.md — 来源摘要页（含作者简介）

确认？（可调整）
```

**分类原则**：
- 定义、框架、方法论、工具 → `concepts/`
- 作者的强主张（反常识、有争议、可被质疑）→ `opinions/`
- 来源摘要（书的全貌）→ `sources/`

#### 3b. 创建页面

**concepts/ 页面格式：**
```markdown
---
type: concept
title: 页面标题
timestamp: 2026-06-27T00:00:00Z
sources: [[书名-来源摘要]]
related: [[相关页面A]], [[相关页面B]]
---

# 页面标题

正文（综合全书相关章节的洞见）...

**主题**：[[主题A]] [[主题B]]
```

**opinions/ 页面格式：**
```markdown
---
type: opinion
title: 命题标题
timestamp: 2026-06-27T00:00:00Z
opinion_of: 作者名
topic: 主题词（2-4字）
sources: [[书名-来源摘要]]
related: []
---

# 命题标题（强主张原文，不超过15字）

**主张**：一两句话陈述核心观点。

**反常识在哪**：这个观点打破了什么默认认知。

**核心证据/论据**：作者用什么支撑。

**可被挑战**：什么情况下这个观点会失效或被反驳。

**主题**：[[主题A]] [[主题B]]
```

**sources/ 页面格式：**
```markdown
---
type: source
title: 书名 — 作者
timestamp: 2026-06-27T00:00:00Z
sources: [/绝对路径/book.pdf]
related: [[相关页面A]]
---

# 书名 — 作者（出版年）

**作者简介**：...

**全书摘要**：...

**章节结构**：...（按章节结构摘要）

**主题**：[[主题A]] [[主题B]]
```

**OKF frontmatter 说明**：`type` / `title` / `timestamp` 三件套是 OKF v0.1 必备字段（2026-06 起 my-wiki 已对齐）。`timestamp` 用 ISO 8601（`YYYY-MM-DDT00:00:00Z`），日期级粒度统一取 `00:00:00Z`。my-wiki 扩展字段 `opinion_of` / `topic` / `sources` / `related` 保留。

**原则：**
- concepts/opinions 按主题组织，不按章节顺序堆砌
- 每个 opinions 页末尾必须加 `**主题**：[[X]]`，连接到 topics/ 中间层
- 来源页（sources/）才写章节结构摘要

#### 3c. 更新元文件

1. 追加 `log.md` 一条记录（格式：`## [日期] ingest | 《书名》 — N 个 concepts，M 条 opinions，1 个 source`）
2. 更新 `index.md` 统计数字（最后两行：页面数 + 最后更新日期）
3. git commit & push

## 注意事项

- **自动逐章阅读**：读完一章后自动继续下一章，无需等用户确认（用户说"先停这里"才暂停）
- **不要跳过提炼**：每章必须输出洞见，不能只说"读完了"
- **保持知识地图**：跨章主题关联是这个 skill 的核心价值
- **PDF 20页硬限制**：单次 Read 调用不超过 20 页，超过的章节分多次调用
- **区分 concept vs opinion**：写 wiki 时强主张写 opinions/，框架定义写 concepts/，不要混淆
- **主题链接必须加**：每个新页面末尾加 `**主题**：[[X]]`，否则节点在图谱中孤立
