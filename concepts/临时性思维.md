# 临时性思维：先建一个还不灵的东西

来源：Cat Wu（Claude Code 产品负责人）访谈。
核心命题：**在 AI 时代，唯一比做错更贵的，是等全想清楚了再做。**

> "It's pretty important to build products that don't necessarily work yet."

---

## 三个反直觉理由

### 理由一：模型边界只有撞上才知道

模型的能力边界是隐性的——看 benchmark 只知道标准任务得分，不知道在你的具体产品场景里卡在哪。是上下文不够长？推理不够深？幻觉率在特定输入下飙升？

必须先建，让它在具体场景里失败，分析失败模式。**"发现→理解→标定"的链路，不可能通过读 paper 或看别人跑分完成。**

案例：代码审查功能。如果等模型够强再做，第一版大概率是"看一段代码变更给点意见"。但 Anthropic 真正做出来的是"多个 agent 同时跑、遍历整个代码仓库、合成真实问题集"——这个产品形态是反复撞边界撞出来的，不是在真空中设计的。

### 理由二：这是唯一的"时间机器"

新模型出来时，谁最先知道它能不能用？是手里已经有原型能立刻换进去测的人——几小时内知道答案。没有原型的团队要从头开始建。

**在模型能力每隔几个月跳一个大台阶的世界里，每次都早别人几天知道——一年下来，对产品的理解已经领先了一个代际。**

### 理由三：AI 产品形态从失败中磨出来

传统软件的产品形态在设计阶段大体确定。但 AI 产品的功能可行性取决于模型边界，而模型边界在你真正撞上去之前是不可知的。

产品形态不是"先想清楚再实现"，而是"先实现出接近的、让它失败、从失败模式里反推更好的形态"。

## 临时性思维：建造时预设拆除路径

这是"先建还不灵的东西"的硬币另一面，与速度引擎第五层（模型变强就删功能）是同一个哲学。

**传统软件**：功能加上去就一直在，像滚雪球只增不减。

**AI 产品**：呼吸式——一呼（加补丁），一吸（拆补丁）。

加一个 prompt 指令时，心里已经标好退场条件："这东西存在的唯一理由，是当前模型在 X 场景下不够好。一旦模型突破临界点，进回收站。"

完整循环：
```
模型还不够好
  → 加补丁（建还不 work 的东西）
  → 从失败中理解缺口，精确标定差多少
  → 新模型出来，立刻换进去测
  → 缺口闭合：拆补丁，回归更简洁形态
  → 缺口还在：更新认知，继续养原型等下一次升级
```

> **传统软件：建造是永久的承诺。AI 产品：临时性不是凑合，是唯一理性的设计哲学。**

## 资源有限的团队怎么玩

有意义，但打法不同。模型趋势是公开信息（上下文更长/推理更深/幻觉更少），任何团队都能基于趋势下注。且原型成本在暴跌：一个工程师 + Claude Code，几天就能搭可测原型。

**关键是选对方向**——选"缺口清晰而且模型方向明确"的来押：
- 缺口清晰：知道自己在等什么
- 方向明确：模型大概率朝那个方向进步

前提：团队有余力。如果还在为核心指标挣扎，预建原型是奢侈品，不是必需品。

## 与战略思维的根本转变

传统 PM：在稳定技术地基上，做长期产品决策。决策有累积性。

AI 时代 PM：在不稳定技术地基上，做一系列**有明确退场条件的短期决策**，叠加出长期优势。

> **不是"知道东西会变"——谁都知道。是在建造的时候就预设了拆除的路径。这不是悲观，是清醒。**
