# 议题树（Issue Tree）

把初始假设分解到子议题形成的树状结构——问题解决的路线图。

## 核心定义

从初始假设出发，在每个议题上进行分解，形成像树一样分支的结构。每个分支末端的议题都应有明确的"是/否"答案或可分析验证的指标。

## 构建方法

1. **从初始假设开始**：顶层是问题本身或核心建议
2. **按 MECE 拆分**：每个层级的子议题相互独立、完全穷尽（见 [[MECE原则-拉塞尔]]）
3. **找到关键驱动因素**：拆到能影响结论的变量为止
4. **叶节点可验证**：每个叶节点对应一个可分析、可证实/证伪的议题

## 经典案例（Acme 装饰品公司）

**顶层问题**：增加装饰品销量

```
├─ 改变销售到零售网点的方式
│   └─ 销售人员按顾客类型重组（而非按区位）
│       └─ 东北区域超市销售经验可否复制到全国？
├─ 改进向顾客营销装饰品的方式
│   └─ 营销渠道优化
└─ 降低装饰品的单位成本
    └─ 业务流程再造降本
```

## 议题树的作用

- **路线图**：明确要做什么分析、收集什么事实
- **避免遗漏**：MECE 保证覆盖所有关键维度
- **聚焦资源**：叶节点对应具体分析任务，可分配给团队成员
- **快速证伪**：某个分支被证伪，砍掉整枝，资源重分配

## 与其他工具的关系

- **vs 思维导图**：思维导图发散性，议题树必须 MECE 且叶节点可验证
- **vs 决策树**：决策树是"如果 X 则 Y"的条件分支，议题树是问题分解
- **vs 5 Why**：5 Why 是纵向深挖根因，议题树是横向 MECE 拆解
