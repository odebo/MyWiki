# 递归结构与模块化

**定义**：技术的**递归结构**（Recursive Structure）指技术由部件和零件构成，而集成件自身也是技术，集成件的子集成件也是技术，递归下去直到基础现象。**模块化**（Modularity）是递归结构的组织形式——技术被功能性分组为可分离的子系统（模块），每个模块独立可替换，大大简化设计过程。

## 递归结构的核心

### 技术的解剖学
- 技术 = 主集成（执行基本原理）+ 次集成（支持主集成运转）
- 次集成 = 子集成 + 子子集成 + ... + 基础元器件
- 基础元器件之下 = 现象（不再属于技术）

### 递归的终点
组合结构一直分解下去，将到达一类**不再属于技术的"现象"或"效应"**：
- 现象具有恒定性
- 现象先于人类存在
- 现象是技术的"原子"

### 递归结构的共同性
所有技术无论外观多么不同，都共享这种解剖学结构：
- 脊椎动物：河马和蛇看起来毫无相像，但都有分节柱状结构+心脏肝脏肾脏神经系统
- 技术：喷气发动机和计算机程序看起来完全不同，但都有主集成+次集成+递归结构

## 模块化的原因

### 1. 简化设计
完全由单一元器件放置组合的技术几乎不存在——除了极端情况。模块化让设计师只需要关心模块间接口，不必理解每个模块内部细节。

### 2. 平衡约束
每个模块必须能在其他模块设定的约束范围内运行（温度、流速、荷载、电压、数据类型、协议）。反过来，每个模块又要为依赖它的模块建立适合的工作环境。

### 3. 现象分离
现象需要被分配到不同模块：
- 不会在电子设备内部将电容器放在感应器旁边（避免不必要振动）
- 不会在飞机发动机测量压力下降装置旁边放置燃烧装置
- 每个模块"驯服"特定现象，避免现象间干扰

### 4. 可替换性
模块可独立替换升级——如喷气发动机中燃料输送系统可独立改进而不必重新设计整个发动机

## 模块化的层级（以喷气发动机为例）

```
喷气发动机（技术整体）
├── 主集成
│   ├── 进气道
│   ├── 压气机
│   ├── 燃烧室
│   ├── 涡轮
│   └── 尾喷管
├── 支持子系统
│   ├── 燃料输送系统
│   ├── 压气机反熄火系统
│   ├── 涡轮叶片冷却系统
│   ├── 发动机仪表系统
│   └── 电气系统
└── 子子系统（每个子系统又有自己的集成件和组件）
    ├── 加热单元（需绝缘和控温组件）
    ├── 计算机算法（需专门编写的软件）
    └── ...
```

## 装置与流程的统一

### 表面差异
- 装置（半导体收音机）= 硬件
- 流程（石油冶炼）= 操作序列

### 实际统一
- 装置总是"按流程处理"某事——收音机"按流程处理"信号
- 流程常常需要物理设备执行——可视为"装置"
- 强调"软件"看到过程和方法；强调"硬件"看到物理设备
- 两者都属于技术，只是不同侧面

## 工作构架（Working Architecture）

- 模块和它们之间的联系共同形成"工作构架"
- 理解技术 = 理解原理 + 理解原理如何转化为工作构架
- 工作构架是技术与原理之间的中介

## 递归性的重要性

1. **组合进化的基础**：因为组件本身是技术，所以新技术可由已有技术作为构件组合而成
2. **模块化的前提**：递归结构使技术可被分解为可管理的模块
3. **现象的终点**：递归不是无限的——现象作为非技术的终点
4. **解释的统一性**：所有技术无论复杂度都共享递归结构——简单铆钉和复杂喷气发动机同构

**应用边界**：
- 递归结构假设"组件本身是技术"——但某些基础组件（如铆钉）是否真是技术有争议
- 模块化的边界是模糊的——何时该合并模块、何时该拆分没有客观标准
- 递归终点的"现象"可能无法完全消除——某些社会/组织技术的"现象"难以界定
- 模块化可能过度分割——导致集成成本超过模块化收益
