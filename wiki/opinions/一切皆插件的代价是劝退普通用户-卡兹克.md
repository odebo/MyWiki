# 一切皆插件的代价是劝退普通用户

**主张**：把 Agent 的全部能力（工具、UI、会话、模式）都插件化、可自定义，理念上极漂亮，但代价是对普通用户极度不友好——过多的开发者术语、过高的使用门槛、过少的功能、过差的体验，每一步都在劝退非开发者。

**反常识在哪**：通常认为"可自定义 = 更强大 = 更好用"，但 DeepSeek Harness 揭示了另一面——当可自定义的范围大到连 UI 和运行模式都要用户自己理解、选择（标准/PTC/极简/创造四种模式已让多数人发懵），自由反而成了负担。

**核心证据/论据**：① 四种模式（标准/PTC/极简/创造）的区分本身就需要相当的底层认知，作者反复建议小白"无脑选标准模式""没事别用极简模式"；② 核心特性（时间/空间可组合性、事件日志、创造模式自进化）全部用开发者术语表达；③ 第一方插件功能有限，需用户自行寻找、安装三方插件补齐体验。

**可被挑战**：这是以"当下普通用户视角"作的判断。若 DeepSeek 未来补齐默认体验、或社区长出高质量开箱即用插件包，"对普通用户不友好"可能只是早期阶段的阵痛而非本质缺陷；DeepSeek 作为注重科研探索的团队，其路线选择本就不以即时可用性为最高优先级。
