# 编程语言的能力有高下之分

**主张**：编程语言的「编程能力」有真实的高下之分，不存在「所有语言都一样」；因此除非特殊情况（与既有系统配合、极简任务、依赖函数库等），否则就应选择最强大的语言，否则就像徒手写机器语言一样愚蠢，只是程度不同。

**反常识在哪**：打破「你用什么语言不重要，重要的是对问题的理解」「不同语言各有千秋」的客套话，以及经理「语言都差不多、选业界标准就行」的舒适假设。格雷厄姆讽刺那些声称「所有语言基本相似」的黑客——那是「吃过麦当劳就以为全世界麦当劳一个味」。

**核心证据/论据**：经理自己随时间的答案变化（1992 年说 C++、今天说 Java）本身就证明语言有差异；ITA 软件公司总裁引述「1 行 Lisp 代码相当于 20 行 C 代码」，使其订票搜索性能比两大巨头高出数个数量级、开发速度快 20 倍；Viaweb 编辑器源码中 20%–25% 是宏，这部分功能其他语言难以实现；格林斯潘第十定律——任何 C 或 Fortran 程序复杂到一定程度，都会内嵌一个残缺的 Common Lisp 实现。

**可被挑战**：语言选择还受函数库、生态系统、招聘、团队熟悉度、与既有系统集成等约束，「最强大」不等于「最适合特定场景」；代码行数与开发效率的相关性有争议（布鲁克斯假说认为程序员日产出的代码行数是常量，与语言无关）；「编程能力」本身难以严格度量，作者以 Lisp 为中心的立场带有自利成分。
